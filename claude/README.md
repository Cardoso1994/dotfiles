# Claude Code Dotfiles

Personal Claude Code configuration managed as dotfiles. Supports two accounts
(`work` and `pers`) with shared settings and per-account overrides.

## Directory Structure

```
dotfiles/claude/
├── skills/                    # Personal skills (shared across all accounts)
│   ├── authoritative-sources/ # Always cite official/authoritative sources
│   └── python-style-guide/    # Google style guide + functional principles
├── settings.base.json         # Settings shared by all accounts
├── settings.work.json         # Work account overrides (permissions, etc.)
├── settings.pers.json         # Personal account overrides
├── install.sh                 # Setup script — run this on a new machine
└── README.md                  # This file
```

## How It Works

### Skills

`~/.claude/skills` is a symlink to `dotfiles/claude/skills`. All skills in
this directory are available in every Claude Code session automatically.

To add a new skill:
```bash
mkdir dotfiles/claude/skills/my-skill
# create dotfiles/claude/skills/my-skill/SKILL.md
# restart Claude Code
```

### Settings

Settings are split into three files:

- `settings.base.json` — shared config (plugins, thinking mode, effort level)
- `settings.work.json` — work-only overrides (e.g. allowed domains, permissions)
- `settings.pers.json` — personal-only overrides

`install.sh` deep-merges base + profile into `~/.claude/settings.json`.
`settings.json` is **not** a symlink because Claude Code writes back to it
interactively (granting permissions, etc.) — merging on demand keeps the repo
clean.

`~/.claude/settings.local.json` is intentionally **not** managed here. Use it
for truly machine-local overrides (one-off paths, temporary permissions).

## Setting Up a New Machine

```bash
# 1. Clone your dotfiles (if not already done)
git clone <your-dotfiles-repo> ~/dotfiles

# 2. Run the installer with your account profile
cd ~/dotfiles/claude
./install.sh work    # or: ./install.sh pers

# 3. Restart Claude Code
```

That's it. The installer:
- Creates `~/.claude/` if it doesn't exist
- Symlinks `~/.claude/skills` → `dotfiles/claude/skills`
- Merges base + profile settings into `~/.claude/settings.json`

## Switching Accounts

When switching between work and personal Claude accounts on the same machine,
re-run the installer with the appropriate profile:

```bash
~/dotfiles/claude/install.sh work   # switch to work
~/dotfiles/claude/install.sh pers   # switch to personal
```

Then restart Claude Code.

## Adding a New Skill

1. Create a directory under `skills/`:
   ```bash
   mkdir dotfiles/claude/skills/my-skill
   ```
2. Create `SKILL.md` with frontmatter `name` and `description` fields.
3. Restart Claude Code — skills are scanned at startup.

The `description` field is what Claude matches against your messages, so make
it explicit about when the skill should trigger.

## Adding Account-Specific Settings

Edit `settings.work.json` or `settings.pers.json` and re-run `install.sh`.
Settings are deep-merged, so nested objects (like `permissions.allow`) are
combined, not replaced.

## What NOT to Commit

- `~/.claude/settings.json` — generated by install.sh, contains merged output
- `~/.claude/settings.local.json` — machine-local overrides
- `~/.claude/projects/` — per-project conversation memory
- `~/.claude/history.jsonl` — conversation history
